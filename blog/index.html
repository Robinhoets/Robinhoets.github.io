DEVELOPMENT LOG 001

Redesigning the Quadcopter:
Bare Metal Programming

August 24, 2026

Original Design

A couple of years ago I built a self balancing quadcopter with arduino and it's built in libraries. While this was no small feat to buy the individual parts, learn about PID and program it, I want to redesign the entire system.

This time I want to program the system bare metal. This means writing all the drivers, libraries and the flight controller.

Before I can read sensors, control motors or implement a flight controller, the STM32 needs a reliable way to interact with the hardware around it.

One of the first pieces of the flight-controller stack I've implemented is a GPIO driver. GPIO, or General Purpose Input/Output, gives the microcontroller a basic interface to external hardware.

For this test I connected a button and LED to the STM32F407 and configured the input to generate an external interrupt. Instead of continuously checking whether the button is pressed, the processor can be interrupted when the event actually occurs.

Why Use an Interrupt?

The simplest way to detect a button would be polling. The processor could continuously read the GPIO pin: 

while (1)
{
    if (GPIO_ReadFromInputPin(GPIOA, GPIO_PIN_NO_5))
    {
        GPIO_ToggleOutputPin(
            GPIOD,
            GPIO_PIN_NO_12
        );
    }
}

That approach works, but the processor has to repeatedly check the input whether anything is happening or not.

With an interrupt, hardware detects the configured event and notifies the processor. Execution temporarily jumps to an interrupt service routine, handles the event and then returns to whatever code was previously executing.

Configuring the GPIO

My GPIO driver uses a handle containing the GPIO peripheral and the configuration for the individual pin. 

GPIO_Handle_t GPIOBtn;

GPIOBtn.pGPIOx = GPIOA;

GPIOBtn.GPIO_PinConfig.GPIO_PinNumber =
    GPIO_PIN_NO_5;

GPIOBtn.GPIO_PinConfig.GPIO_PinMode =
    GPIO_MODE_IT_FT;

GPIOBtn.GPIO_PinConfig.GPIO_PinSpeed =
    GPIO_SPEED_FAST;

GPIOBtn.GPIO_PinConfig.GPIO_PinPuPdControl =
    GPIO_PIN_PU;

GPIO_Init(&GPIOBtn);

In this case, the pin is configured as an interrupt input triggered by a falling edge.

Falling Edge

A falling-edge event occurs when the signal changes from a logic HIGH state to a logic LOW state.

Handling the Interrupt

Once the configured external interrupt fires, execution enters the appropriate interrupt handler: 

void EXTI9_5_IRQHandler(void)
{
    GPIO_IRQHandling(GPIO_PIN_NO_5);

    GPIO_ToggleOutputPin(
        GPIOD,
        GPIO_PIN_NO_12
    );
}

The first operation clears the pending interrupt flag. The LED output is then toggled before returning from the handler.

Keeping an interrupt handler short is important. An ISR prevents normal execution from continuing while it runs, so lengthy processing inside the handler can interfere with other time-sensitive work.

Hardware Test

This is the actual GPIO interrupt running on the STM32F407 development board.

Why This Matters for the Quadcopter

Toggling an LED obviously isn't the final objective. This is a small hardware test for infrastructure that becomes much more important as the flight controller develops.

A flight controller needs to react to hardware events while simultaneously performing sensor acquisition, state estimation, control calculations and motor output.

Interrupts provide one of the mechanisms that allows the STM32 to respond to those events efficiently without continuously polling every peripheral.
